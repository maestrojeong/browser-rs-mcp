# Engineering review: porting CUA `browser_pointer` into `browser-rs-mcp`

## Verdict

**Partial go.** Port the route contract, missing actions, DOM-event implementations, stale-ref/frame checks, mutation serialization, and structured outcomes; do **not** transplant CUA's trusted dispatcher or its native-window/endpoint subsystem wholesale. The strongest reason is that `browser-rs-mcp` already has a more stealth-conscious trusted path (curved continuous motion, off-center aim, randomized dwell), while CUA's real advantage is its exact-or-refused identity architecture, which cannot be obtained by copying `pointer.rs` alone.

This is a static review of target version `0.1.21` at commit `1fa667f`. No source or runtime behavior was changed or exercised. The pre-existing `README.md` worktree modification was left untouched.

## 2. Gap analysis

**Genuinely new from CUA:** `PointerAction` covers `right_click` and `double_click`, and accepts ref or coordinates with horizontal/vertical scroll and drag destinations (`pointer.rs:27-59,105-208`). `input_route` is explicit: `trusted` or ref-only `dom_event` (`pointer.rs:80-103,176-178`), so an untrusted event is never a silent fallback. The DOM route supplies full background hover, context menu, double-click/`dblclick`, wheel plus programmatic scroll, and HTML drag with `DataTransfer`/`DragEvent` (`pointer.rs:395-527`). Its DOM scroll returns false unless `scrollLeft`/`scrollTop` changed (`pointer.rs:436-438,485-522`).

**Safety/identity new from CUA:** refs are `p<snapshot>:<index>` capabilities carrying `backendNodeId`, action set, `FrameKind`, OOPIF target, and `frame_id + loader_id` (`store.rs:1-16,29-38,80-166,233-252`). Ref resolution is session/target/tab/snapshot/generation scoped (`store.rs:297-374`). Before dispatch, CUA serializes by real process/target (`engine.rs:1566-1585`), revalidates process fingerprint, native window ownership, endpoint, CDP window, and tab (`engine.rs:1277-1426`), then re-proves frame/document identity and OOPIF ancestry (`engine.rs:1666-1755`). Drag refuses mixed or unprovably different frames (`pointer.rs:833-864`). Stable machine-readable refusals are defined in `refusal.rs:17-126`.

**Already present, not a reason to port:** CDP `mouseMoved`, left press/release, `mouseWheel`, eight-step drag, `DOM.scrollIntoViewIfNeeded`, `DOM.getBoxModel`, `DOM.resolveNode`, and constructed DOM click/hover events all exist in the target. In fact, target `human_move_to` and off-center aim (`lib.rs:1154-1224,2854-2863`) are behaviorally richer than CUA's exact-center single move/eight linear drag (`pointer.rs:248-280,677-724`).

**Important qualification:** CUA's exactness is mainly target/ref/delivery exactness, not universal effect proof. The DOM scroll proves a scroll offset changed and DOM drag proves destination resolution; trusted scroll/drag only prove CDP acknowledged dispatch (`pointer.rs:603-649,677-724`). Hover/right/double DOM success likewise proves the page-side function returned, not that application state changed. The review should not market CUA as proving every pointer effect.

## 3. Architecture fit

`ab-cdp` should remain a dumb transport. Its existing `send_on` already supports every required command; only a generally useful connection generation/closed-state abstraction would belong there, and CUA's whole `cdp_ws.rs` should not replace it.

`ab-browser` should own a new `pointer.rs` module and typed `PointerAction`, `InputRoute`, `PointerLocation`, `PointerRequest`, and `PointerOutcome`. It should reuse `Page`, `CdpClient`, `human_move_to`, `node_center`, `resolve_object`, and `scroll_into_view`. Add a per-`Page` async mutation mutex so ref validation, dispatch, cleanup, and observation cannot interleave. Move current click/hover/wheel/drag mechanics behind one dispatcher while retaining their public wrappers.

The prerequisite is a stronger ref abstraction spanning `ab-browser::snapshot` and `ab-mcp::PageEntry`: include a monotonically unique snapshot id plus `target_id`, `frame_id`, `loader_id`, OOPIF session/target when applicable, and declared action kinds. Re-check `Page.getFrameTree` and node liveness immediately before mutation. This directly resolves the open ref-stability issue already acknowledged in `DESIGN.md:139-143`. Do not claim CUA-grade native exactness unless `Browser::connect` also gains process/endpoint/native-window attestation; for browser-rs-owned `Browser`/`Page`, target/session/document exactness is the appropriately scoped guarantee.

`ab-mcp` should expose `browser_pointer` for right-click, double-click, coordinate forms, route selection, and horizontal scroll, while keeping `browser_click`, `browser_hover`, `browser_wheel`, and `browser_drag` as compatibility wrappers. Register schemas and map typed refusals to structured MCP content. Owner scoping remains in the existing common page resolver (`main.rs:699-724`); it is complementary to, not a replacement for, snapshot/document identity.

## 4. Anti-detect and stealth assessment

Keep `trusted` as the default. CDP `Input.dispatchMouseEvent` enters Blink's trusted input path, whereas events built with `new PointerEvent`, `MouseEvent`, `WheelEvent`, or `DragEvent` have `isTrusted == false`; many applications reject them and detectors can record that directly. The DOM route is a compatibility/background route, not a stealth route, and its response must say `trusted: false`. Its `Runtime.callFunctionOn` does not require `Runtime.enable`, so it preserves the target's protocol-level omission policy, but it runs observable main-world event constructors against the page's element.

CUA's `Emulation.setFocusEmulationEnabled(true)` around every trusted action (`pointer.rs:603-649`) should **not** be copied as the unconditional default. It may temporarily change `document.hasFocus()`/focus event behavior and creates an input pattern unlike a naturally backgrounded headful tab. Make it an explicit `background_focus_emulation` policy used only after measuring platform behavior, always restore it, and preserve CUA's non-retryable `delivery: unknown` outcome if cleanup fails. Never combine it with implicit `Target.activateTarget`; activation remains the caller's explicit tool.

Do not replace the target's humanized path with CUA's dispatcher: CUA right/double click has no randomized approach/dwell, double-click emits both pairs without an inter-click delay, and ref points are exact centers. Adapt those actions to `human_move_to`, off-center aim, realistic press/release and inter-click timing. Conversely, remove the current silent synthetic fallback from trusted click/hover: it can turn an expected `isTrusted` event into detectable page script while reporting the same success.

Current detector coverage is insufficient for this change. `bench/detector.html:28-110` checks static fingerprint properties and an unscored CDP console probe; it does not inspect `event.isTrusted`, event order, coordinates/timestamps, focus/visibility transitions, or background delivery. Before release, add a local interaction fixture and runner covering those signals for trusted, DOM, foreground, and background cases, then retain `bench/rebrowser.mjs` as the external regression gate.

## 5. Reuse recommendation and prioritized plan

1. **First, fix identity correctness.** In `ab-browser/src/snapshot.rs`, mint snapshot-scoped refs with frame/loader identity and action kinds; in `ab-mcp/src/main.rs`, replace the bare ref map in `PageEntry`; in `ab-browser::Page`, add per-target mutation serialization and live frame/node revalidation. Adapt CUA `FrameIdentity`, `FrameRef`, `same_exact_frame`, generation-scoped lookup, and refusal concepts (`store.rs:104-166,335-374`; `pointer.rs:217-245,833-864`). Skip CUA's process fingerprint/native-window/endpoint code unless attached-existing-browser threat boundaries are separately expanded.
2. **Add the typed pointer core.** Create `crates/ab-browser/src/pointer.rs`; port nearly verbatim the small action/route/location enums, input validation, DOM event sequences, same-frame rules, and DOM-scroll changed-offset check (`pointer.rs:27-208,217-221,423-527`). Adapt all CDP calls to `CdpClient::send_on`, refs to the new target model, and outcomes to `BrowserError`/typed refusal. Preserve MIT attribution if substantial CUA code is copied into this Apache-2.0 repository.
3. **Integrate, do not duplicate, trusted input.** Reuse target `human_move_to`, randomized timing, off-center box point, and current wheel/drag mechanics. Add right button, double-click with realistic timing, `delta_x`, and coordinate variants. Add focus emulation only as an explicit measured policy; no trusted-to-DOM automatic fallback.
4. **Expose MCP compatibility.** Add `browser_pointer` in `ab-mcp/src/main.rs`, and make existing click/hover/wheel/drag tools thin wrappers over it. Return structured fields for route, `trusted`, target/page, snapshot/frame, coordinates, dispatch state, observed state, and retryability. Preserve `settle_diff` as `observed`, but distinguish `changed`, `unchanged`, and `unknown`; do not call it proof of activation.
5. **Test the contracts.** Port CUA's parser, nonzero finite scroll, route/ref requirement, and exact-frame tests (`pointer.rs:892-1003`); add stale-ref alias, navigation/loader change, OOPIF mismatch, concurrent mutation, cleanup-failure, untrusted-event, focus-transition, scroll-at-boundary, and realistic double-click tests. Run unit/clippy plus the local detector and `bench/rebrowser.mjs` before release.

**Port verbatim:** small pure enums/parsers/tests and, subject to attribution, the DOM event sequence bodies and scroll movement predicate. **Adapt:** ref/store model, frame checks, mutation lock, structured refusal/outcome shape, and focus-emulation cleanup. **Skip:** CUA's CDP pool, native platform binding/preparation/consent machinery, exact-center trusted motion, unconditional focus emulation, and duplicate trusted hover/wheel/drag dispatch.
